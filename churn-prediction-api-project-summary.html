Key Design Decisions (Interview-defensible)

Why SMOTE over class_weight?

The Telco dataset has ~26% churn. class_weight only re-weights the loss — trees still see the imbalanced feature distribution during split-search. SMOTE synthesises minority samples before fitting, improving recall on churned customers (+3–5%). Applied only inside imblearn.Pipeline so it never leaks into validation/test folds.

Why XGBoost, not a neural net?

~7k rows of tabular data. XGBoost consistently outperforms DNNs at this scale, trains in seconds, is natively interpretable via SHAP's TreeExplainer (exact Shapley values, not sampling-based), and is the industry standard for structured churn modelling.

Why Mangum for Lambda?

Lambda expects handler(event, context). Mangum translates API Gateway / Function URL HTTP events into ASGI scope/receive/send — zero code changes to the FastAPI app. The same uvicorn api.main:app runs both locally and in Lambda.

lru_cache on model load

Lambda containers are reused across invocations. @lru_cache(maxsize=1) on _load_artifacts() ensures the ~150 MB model is loaded from disk exactly once per container lifetime, then served from memory for all subsequent requests.
